# Taxichi Pro: план защиты и серверной оплаты

Этот файл нужен, чтобы включать безопасность по шагам и не сломать текущие сайты/приложение.

## Уже подготовлено в коде

- Админ входит только по логину/паролю, которые заведены в директорском кабинете.
- Директор может открыть админский кабинет через временную ссылку на 10 минут.
- Временный вход директора открывает админку в режиме просмотра: кнопки изменения, удаления, пополнения и списания отключены.
- Ошибки входа показываются явно:
  - `Логин или пароль неверно, обратитесь в поддержку`
  - `Сервер не отвечает. Проверьте интернет или обратитесь в поддержку`

## Что включать на сервере

1. Выполнить `supabase-security-hardening.sql`.
2. Развернуть Edge Functions из папки `supabase/functions`.
3. Добавить secrets в Supabase:
   - `SUPABASE_URL`
   - `SUPABASE_SERVICE_ROLE_KEY`
   - `YOOKASSA_SHOP_ID`
   - `YOOKASSA_SECRET_KEY`
   - `YOOKASSA_RETURN_URL`
4. Подключить webhook в ЮKassa:
   - `https://<project-ref>.supabase.co/functions/v1/yookassa-webhook`
5. После перехода сайтов на серверные функции включить строгие RLS-политики.

## Почему RLS нельзя включить одним кликом сейчас

Текущие сайт и APK работают напрямую через publishable/anon key. Если сразу закрыть таблицы RLS без серверного шлюза, админка, директорский кабинет и приложение потеряют доступ к данным.

Правильный порядок:

1. Сначала добавить серверные функции.
2. Перевести запись важных операций на сервер:
   - выпуск ЭПЛ;
   - списание баланса;
   - оплата подписки;
   - удаление админа/водителей;
   - аудит.
3. Потом включить RLS.
4. После миграции заменить открытые пароли на `password_hash`.

## Что проверять перед продвижением

- вход админа с другого компьютера;
- вход директора;
- открытие админки директором в режиме просмотра;
- запрет изменений в режиме просмотра;
- единые данные на другом браузере/телефоне;
- успешный и ошибочный платеж ЮKassa;
- webhook после оплаты;
- продление подписки после webhook;
- запрет выпуска ЭПЛ при оконченной подписке.
